# Brickhold website direction

The site takes its presentation direction from the user's references: [Aggro Crab](https://aggrocrab.com/), [PEAK](https://peakpeakpeak.com/), and their own earlier [Tidy Tides](https://www.tidytides.co.za/) website. These were reviewed in a real browser. Full-screen game scenery, expressive type and a page that shares the game's theme guide the design; their artwork, logos and CSS are not copied.

The user approved the brick layouts, portal-purple, gold, parchment and soft green treatment. That design remains: castle battlements connect sections, screenshots sit in an angled print-like frame, the field guide uses collectible cards, and contact uses a raven-stamped postcard.

The follow-up replaces the initial concept imagery and temporary marks with the user's actual marketing files from Downloads. The opening uses an in-game portal scene and the supplied Brickhold logo. The actual Broken Robot studio logo appears in navigation, the studio sign and footer; the original robot also supplies the favicon. The gallery shows the world, building, barricade routing, trap defense, combat and guardians. Both downloaded animations are available on request, with still images by default.

The field guide covers all eight defenses and eleven enemies from the supplied roster sheets. Each card uses a screenshot crop, with its name, role, description and any trap cost visible directly on the card. The traps and The troublemakers each display their full collection at once. Cards are non-clickable articles; they retain the hover lift and playful paper/stud treatment, with no pagination, plus icons, detail buttons or dialogs. The supplied itch screenshot informs the collection density and content; its page layout and background are not reproduced.

A third tab, Kingdoms, introduces the maps with the actual Playground arena and its aerial in-game capture. Map data lives in `content/site.json`; no extra kingdoms or future map names have been invented. Beneath the tab panels, a small “Choose your Shardkeeper” preview uses the supplied hero portrait. This is the place reserved for a future playable-hero roster, without inventing hero classes, abilities or selection controls before that roster is ready.

The four independently built React sections and optional local BFF remain. Navigation, collection tabs, image choices, animation controls and contact actions are keyboard accessible. The collection tabs use selected states, associated panels and Arrow/Home/End keyboard navigation. Reduced-motion preferences disable the opening scene's pointer movement and keep gameplay still until explicitly played. The production artifact is checked at domain root and beneath a GitHub Pages repository path.

The opening scene has a restrained layer of drifting purple particles, a six-pixel nudge on the scroll icons and a slow halo around the green development dot. Only transforms and opacity animate; the text and buttons stay still. A small pause control freezes the decorative motion and pointer response, and the effects pause while the scene is offscreen. Reduced-motion preferences remove these animations entirely. Phones use fewer particles.
